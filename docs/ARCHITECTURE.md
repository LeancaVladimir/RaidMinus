# RaidMinus — архитектура

Аддон для РЛа. Команды: `/rm`, `/минус`. Сервер WoW Circle 3.3.5a (ruRU), ЦЛК 25.

## 1. Смысл

После последнего босса весь лут разыгрывается роллом. В течение рейда РЛ ставит игрокам минусы
за ошибки и плюсы за заслуги. На розыгрыше к броску каждого прибавляется его сумма:

```
итог = /roll (1–100) + сумма плюсов и минусов за этот рейд
```

Кроме очков, правило может пометить игрока **«на кик»** — он не побеждает в ролле.
Часть правил ловит автоматика (журнал боя, Skada, DBM) — см. [AUTOMATION.md](AUTOMATION.md).

## 2. Принятые решения (13.10.2026)

| Вопрос | Решение |
|---|---|
| Срок жизни минусов | Один рейд. «Завершить рейд» обнуляет и переносит журнал в историю (20 последних) |
| Кто ставит минусы | Только РЛ. Синхронизации между аддонами нет |
| Категории лута | Тринкеты — по слоту, с любого босса. Оружие с Лича — список предметов Лича 25 об./гер. (из AtlasLoot). «Остальной лут» — всё прочее. Категорию «лёд» из второго свода не делаем: не знаем, что это |
| Отдельный аддон | Да, полностью отдельный от SkadaDiscord, свой репозиторий |
| Диапазон ролла | Засчитывается `/roll` 1–100 (настройка) |
| Офф-спек | Отдельный ролл после основного: кнопка «Ролл на офф-спек» (минусы считаются так же, итог помечен «офф-спек») |
| Шёпот `!правила` | Убран; остаётся только `!минус` |
| Роль игрока | Основная роль на рейд (танк / хил / мдд / рдд) — первая замеченная по спеку (LibGroupTalents из DBM) или выставленная РЛом (ПКМ по игроку). Хил, переодетый на Орке в ДД, остаётся хилом: планка ДПС его не касается. Охотник — рдд |
| Итог ролла в чат | Победитель в рейд-варнинг, затем каждый игрок отдельной строкой: `{rt1} 1. Имя — 35 (80 -45) — победитель`, ничья `{rt3}`, не засчитан `{rt7}`. Строки идут с паузой 0,35 сек (защита от флуда) |
| Чужой ролл | Лидер, ассистент или ответственный за добычу пишет «ролл [предмет]» → предмет в списке, броски тихо считаются с минусами. В чат — только по «Закончить розыгрыш» |
| Добыча с босса | Открыл тело (или ответственный скинул список) → окошко «Добыча» с «+» и «Добавить всё» |
| Автоматика | 17 встроенных автоправил (выбор РЛа), по умолчанию −10, находки — во вкладку «На проверку». У каждого правила: «Включено» и «Ставить сразу» (минус игроку без проверки) — в редакторе и по ПКМ в окне. Список — [AUTOMATION.md](AUTOMATION.md) |
| Метки правил | Красная — автоматика, оранжевая — видно, кто нарушил, белая — только вручную |
| Запрет ролла | Убран (РЛ: бесполезно). Не побеждает в ролле только тот, кто «на кике» |

### 0.3.0 (16.10.2026) — по отчётам игроков после настоящих рейдов на 0.2.1

| Вопрос | Решение |
|---|---|
| Двойной ролл | Синхронизация через канал аддонов «RaidMinus» (`Sync.lua`): RS/RE/RC — ролл начат / итог / отменён, AW — кто получил, LT — содержимое тела, TT — время на передачу из сумки, HI — «я после /reload». Пока виден чужой ролл, «Начать ролл» недоступна; разыгранное другим второй раз не разыграть. Минусы не синхронизируются — их ставит РЛ у себя; если у разыгрывавшего победитель другой, видно обоих |
| Кто разыгрывает | Только РЛ, помощник и ответственный за добычу (`ns.CanManageLoot`); тестовый рейд и игра без группы — можно |
| Добыча Профа «не записалась» | Причина: фильтр знал только ЦЛК 25 гер., а босса убили на обычной — его вещи 264 прятались. Теперь таблицы всех сложностей (10/10 гер./25/25 гер.), фильтр «boss» по умолчанию, «только гер.» — по желанию. Журнал источников `/rm лог` |
| Время на передачу | 2 часа с момента, как предмет взяли из тела: точно — из подсказки в сумке (и от лутера через TT), почти точно — по строке «получает добычу», иначе оценка от убийства (~). Предупреждения за 15 и 5 минут (`TradeTime.lua`) |
| История | Вкладка «История»: рейды, добыча (победитель, ролл ± = итог, получил), игроки; отчёт текстом для Discord |
| Пул раньше таймера не ловился | Причина: DBM-wowcircle делает /pull «пиццей» «Атака» (DBMv4-Pizza), а не DBMv4-PT. Теперь: перехват `DBM:CreatePizzaTimer`, оба сообщения DBM, запасной разбор «Атака через N сек.»; виноват первый, кто тронул босса (урон, дебаф, таунт; питомец — хозяин), время — по первому удару. Строка в чате после пула, журнал `/rm лог пул` |
| Выиграл один, получил другой | `e.receiver`: клик по игроку в таблице бросков + «Закончить розыгрыш» (или «Отдать другому» — список рейда); сам — по строке «X получает добычу» и по моему обмену, но только для уже разыгранного (до ролла взявший — `e.holder`, держит). Виден в истории и у других (AW). В итог в чат идёт он, а не победитель по броскам |
| Итог в чат | Одна строка в обычный чат рейда: «[предмет] — Имя» (или «— никто», «— ничья: …»). Таблица бросков с минусами — только в окне. Объявление начала ролла и переролла ничьей — по-прежнему в объявление рейду (игрокам надо бросать). Настройка «строк итога» убрана |
| Чужой ролл «не виден» (второй отчёт) | Без «Начать рейд» аддон не слушал чат, а начатый подсчёт шёл молча во вкладке. Теперь: рейд начинается сам (`autoSession`) — ролл в объявлении рейду или пул босса в рейдовой группе; начало чужого ролла — строка в чате и окно на «Розыгрыше» с этим предметом (`rollPopup`); синие/зелёные ссылки — ролл, если пошли броски |
| Чужой ролл не подхватывался | Обычно ролл — это ссылка на предмет в объявлении рейду (/ов) без слов. Теперь: одна ссылка в объявлении рейду от РЛа/помощника/лутера — ролл; ссылка без слов в обычном чате — ролл, если в ближайшие 30 сек пошли броски (первый бросок тоже засчитан); свои ручные объявления РЛа тоже считаются, кроме написанного самим аддоном (`ns.SentByAddon`) |

Решения РЛа (заменяют строки про автоматику, кик, поля правила и источники добычи выше):

| Вопрос | Решение |
|---|---|
| Встроенная автоматика | Убрана целиком (Detect.lua, Metrics.lua, Data/Detectors.lua) и вкладка «Проверка» (находки, очередь) |
| Правило | Только текст, раздел, минус/плюс и очки. Убраны: кик, текст в чат, пояснение, повтор, нарастание, кому (роли), сложность, своё объявление, шёпот игроку, быстрый доступ, «видно, кто нарушил». Кика больше нет — в ролле не допускается только бросок не того диапазона |
| Автоматика | У правила может быть триггер с условиями — как в WeakAuras, но внутри RaidMinus (переносить аддон в WeakAuras РЛ не стал). Типы, условия, свой код — [AUTOMATION.md](AUTOMATION.md). Сработал — минус сразу; снять — в журнале |
| Старые автоправила | Стали шаблонами (кнопка «+ Шаблон»); старые своды переносятся при загрузке — триггеры выключены, включает РЛ. Строки RM1 читаются, экспорт — RM2; чужой «свой код» приходит выключенным |
| Повтор, сложность, роль | Только в условиях триггера; ручной клик ставит всегда |
| Добыча | Два пути: «в сумку» (строка «X получает добычу», X — РЛ, помощник или ответственный; эпик, не мусор) — запись с таймером 2 ч; «ролл сразу» — ссылка в объявлении рейду → подсчёт и окно «Розыгрыш». Убраны: тело, RaidRoll, списки ссылок, LT в синхронизации, страницы боссов, окно и вкладка «Добыча», фильтр и его настройки |
| Дубли | Объявление берёт неразыгранную запись того же предмета, затем разыгранную без победителя (переролл); разыгранное с тела, что ответственный взял в сумку, — та же запись (держит до передачи) |
| Кнопка «Ролл» | В строке неразыгранного предмета во вкладке «Розыгрыш» |
| Мини-панель и «минус цели» | Правила текущего босса, затем «Общие»; счётчик «Розыгрыш» вместо «Проверка» и «Добыча» |

## 3. Принципы

1. **Решает РЛ.** Триггер ставит минус только по правилу, которое РЛ сам включил. Любую запись можно
   снять с причиной, и снятая запись остаётся в журнале.
2. **Правила — это данные.**
   - РЛ правит свод в игре (`/rm правила`), триггер — там же, как в WeakAuras.
   - Сводом можно поделиться строкой `RM2:...` (сжатие LibDeflate; со своим кодом строка длиннее).
     Старые строки `RM1:...` читаются.
   - Запись журнала хранит текст и очки правила целиком, поэтому правка свода не меняет историю.
3. **Игроку аддон не нужен.**
   - Шёпот `!минус` возвращает сумму и список, `!правила лана` — правила босса.
   - Новые минусы объявляются в рейд одним сообщением: после серии кликов или после боя.
4. **Защита от вылета.** WoW пишет SavedVariables только при /reload и выходе. Поэтому после
   убийства босса аддон предлагает /reload. Если стоит SkadaDiscord, окно не появляется: тот
   перезагружает интерфейс сам.

## 4. Как проходит рейд

1. «Начать рейд» → аддон запоминает состав (и всех, кто заходил потом).
2. `DBM_Pull` → аддон знает текущего босса и номер пула; в окне сразу открыты правила этого босса.
3. Клик по игроку (Ctrl — несколько, Shift — весь класс) → клик по правилу → минус поставлен.
   - Есть свой минус: число и причина.
   - Есть «Отменить последнее»: необъявленное удаляется молча, объявленное снимается с объявлением.
4. Объявление в /рейд: «Леди: Вася -30 (Дух); Петя -20 (Не снял оружие под МК)».
   Пояснение в скобках в конце текста правила в чат не идёт.
5. Спор: вкладка «Журнал» → «Снять» → причина. «Вернуть» восстанавливает запись.
6. Розыгрыш (раздел 6).
7. «Завершить рейд».

## 6. Розыгрыш

1. **Добыча** (`LootList.lua`, список `s.loot`) — два пути:
   - **В сумку:** строка «X получает добычу» (`CHAT_MSG_LOOT`), X — РЛ, помощник или ответственный, эпик и не
     мусор (осколок, саронит, эмблемы — `Data/Loot.lua`) → запись «в сумке у X», 2 часа на передачу.
     Если X — победитель разыгранного, это «получил»; если предмет только что (15 мин) разыграли с тела —
     та же запись, X держит до передачи. Обычный игрок получил предмет — только «получил».
   - **Ролл сразу:** одна ссылка в объявлении рейду от РЛа/помощника/ответственного → наблюдение за
     роллом и окно «Розыгрыш». Запись: неразыгранная того же предмета, затем разыгранная без победителя
     (переролл), иначе новая.
   - Босс записи — по таблице ЦЛК (все сложности), иначе последний убитый (15 мин).
   - Вручную: shift+клик по предмету в поле или перетащить предмет; кнопка «Ролл» в строке.
   - Командой: `/rm ролл [предмет]` (сразу начать) или `/rm лут [предмет]` (только в список).
2. **«Начать ролл».** Объявление в рейд-варнинг: «Ролл [предмет] (оружие с Лича): /roll, 30 сек».
   За 10 сек до конца — напоминание.
3. **Броски** разбираются по шаблону из `RANDOM_ROLL_RESULT` (плюс запасной разбор).
   - Засчитываются только игроки группы и только первый бросок 1–rollMax.
   - Повторные броски показываются в таблице.
   - Если сначала бросил не тот диапазон, засчитывается следующий правильный.
4. **Таблица:** место, игрок, роль, ролл, ±, итог, причина недопуска; победитель — со звездой и подсветкой.
   Наведите на строку — видно, за что у игрока минусы.
5. **Итог.**
   - Ничья на первом месте → переролл только для этих игроков (15 сек), итог считается так же.
   - Победитель объявляется в рейд-варнинг. Затем в /рейд каждый игрок отдельной строкой
     (до rollLines, по умолчанию 10): победитель со звездой, ничья с ромбом, незасчитанные с крестом.
   - «Закончить розыгрыш» досрочно закрывает приём бросков и пишет итог в чат.
   - Чужой ролл: в чат пишется только по «Закончить розыгрыш» или «Итог в чат». Если
     ответственный сам объявил победителя («выиграл»), наблюдение закрывается молча.
6. Текущий ролл живёт в памяти: после /reload посреди ролла его нужно начать заново.
