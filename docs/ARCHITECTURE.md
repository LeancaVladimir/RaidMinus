# RaidMinus — архитектура

Аддон для РЛа. Команды: `/rm`, `/минус`. Сервер WoW Circle 3.3.5a (ruRU), ЦЛК 25.

## 1. Смысл

После последнего босса весь лут разыгрывается роллом. В течение рейда РЛ ставит игрокам минусы
за ошибки и плюсы за заслуги. На розыгрыше к броску каждого прибавляется его сумма:

```
итог = /roll (1–100) + сумма плюсов и минусов за этот рейд
```

Кроме очков, правило может пометить игрока **«на кик»** — он не побеждает в ролле.
Часть правил ловит автоматика (журнал боя, Skada, DBM) — см. [AUTOMATION.md](AUTOMATION.md).

## 2. Принятые решения (13.10.2026)

| Вопрос | Решение |
|---|---|
| Срок жизни минусов | Один рейд. «Завершить рейд» обнуляет и переносит журнал в историю (20 последних) |
| Кто ставит минусы | Только РЛ. Синхронизации между аддонами нет |
| Категории лута | Тринкеты — по слоту, с любого босса. Оружие с Лича — список предметов Лича 25 об./гер. (из AtlasLoot). «Остальной лут» — всё прочее. Категорию «лёд» из второго свода не делаем: не знаем, что это |
| Отдельный аддон | Да, полностью отдельный от SkadaDiscord, свой репозиторий |
| Диапазон ролла | Засчитывается `/roll` 1–100 (настройка) |
| Офф-спек | Отдельный ролл после основного: кнопка «Ролл на офф-спек» (минусы считаются так же, итог помечен «офф-спек») |
| Шёпот `!правила` | Убран; остаётся только `!минус` |
| Роль игрока | Основная роль на рейд (танк / хил / мдд / рдд) — первая замеченная по спеку (LibGroupTalents из DBM) или выставленная РЛом (ПКМ по игроку). Хил, переодетый на Орке в ДД, остаётся хилом: планка ДПС его не касается. Охотник — рдд |
| Итог ролла в чат | Победитель в рейд-варнинг, затем каждый игрок отдельной строкой: `{rt1} 1. Имя — 35 (80 -45) — победитель`, ничья `{rt3}`, не засчитан `{rt7}`. Строки идут с паузой 0,35 сек (защита от флуда) |
| Чужой ролл | Лидер, ассистент или ответственный за добычу пишет «ролл [предмет]» → предмет в списке, броски тихо считаются с минусами. В чат — только по «Закончить розыгрыш» |
| Добыча с босса | Открыл тело (или ответственный скинул список) → окошко «Добыча» с «+» и «Добавить всё» |
| Автоматика | 17 встроенных автоправил (выбор РЛа), по умолчанию −10, находки — во вкладку «На проверку». У каждого правила: «Включено» и «Ставить сразу» (минус игроку без проверки) — в редакторе и по ПКМ в окне. Список — [AUTOMATION.md](AUTOMATION.md) |
| Метки правил | Красная — автоматика, оранжевая — видно, кто нарушил, белая — только вручную |
| Запрет ролла | Убран (РЛ: бесполезно). Не побеждает в ролле только тот, кто «на кике» |

| Пул раньше таймера не ловился | Причина: DBM-wowcircle делает /pull «пиццей» «Атака» (DBMv4-Pizza), а не DBMv4-PT. Строка в чате после пула, журнал `/rm лог пул` |
| Выиграл один, получил другой | `e.receiver`: вручную («Получил другой»), сам — по строке «X получает добычу» (X не ответственный) и по моему обмену; виден в истории и у других (AW) |

## 3. Принципы

1. **Решает РЛ.** Автоматика (этапы 2–3) будет только предлагать. Любую запись можно снять с
   причиной, и снятая запись остаётся в журнале.
2. **Правила — это данные.**
   - РЛ правит свод в игре (`/rm правила`).
   - Сводом можно поделиться строкой `RM1:...` (сжатие LibDeflate, обычно меньше 2000 символов —
     помещается в одно сообщение Discord).
   - Запись журнала хранит текст и очки правила целиком, поэтому правка свода не меняет историю.
3. **Игроку аддон не нужен.**
   - Шёпот `!минус` возвращает сумму и список, `!правила лана` — правила босса.
   - Новые минусы объявляются в рейд одним сообщением: после серии кликов или после боя.
4. **Защита от вылета.** WoW пишет SavedVariables только при /reload и выходе. Поэтому после
   убийства босса аддон предлагает /reload. Если стоит SkadaDiscord, окно не появляется: тот
   перезагружает интерфейс сам.

## 4. Как проходит рейд

1. «Начать рейд» → аддон запоминает состав (и всех, кто заходил потом).
2. `DBM_Pull` → аддон знает текущего босса и номер пула; в окне сразу открыты правила этого босса.
3. Клик по игроку (Ctrl — несколько, Shift — весь класс) → клик по правилу → минус поставлен.
   - Есть свой минус: число и причина.
   - Есть «Отменить последнее»: необъявленное удаляется молча, объявленное снимается с объявлением.
4. Объявление в /рейд: «Леди: Вася -30 (Дух); Петя -20 (Не снял оружие под МК)».
   Пояснение в скобках в конце текста правила в чат не идёт.
5. Спор: вкладка «Журнал» → «Снять» → причина. «Вернуть» восстанавливает запись.
6. Розыгрыш (раздел 6).
7. «Завершить рейд».

## 6. Розыгрыш

1. **Добыча** (`LootList.lua`, страницы по боссам `s.drops`).
   - Источники: своё тело (`LOOT_OPENED`), RaidRoll другого игрока (`CHAT_MSG_ADDON`, префикс `RRL`,
     форматы `Beta_2` и `Alpha`, только канал рейда/группы), строки «X получает добычу» (`CHAT_MSG_LOOT`),
     список ссылок от лидера/ассистента/ответственного.
   - Босс страницы — по таблице предметов ЦЛК 25 гер., иначе по имени тела, иначе последний убитый (15 мин).
   - Без повторов: у каждого источника свой счёт предметов (`tallies`), на странице столько экземпляров,
     сколько назвал самый щедрый источник. Строка чата сначала «подтверждает» уже известный предмет.
   - Фильтр (`Data/Loot.lua`): гер. снаряжение, жетоны, маунт — сразу в розыгрыш (`lootAuto`);
     прочее — «скрыто фильтром», можно добавить «+».
   - Вручную: shift+клик по предмету в поле или перетащить предмет.
   - Командой: `/rm ролл [предмет]` (сразу начать) или `/rm лут [предмет]` (только в список).
2. **«Начать ролл».** Объявление в рейд-варнинг: «Ролл [предмет] (оружие с Лича): /roll, 30 сек».
   За 10 сек до конца — напоминание.
3. **Броски** разбираются по шаблону из `RANDOM_ROLL_RESULT` (плюс запасной разбор).
   - Засчитываются только игроки группы и только первый бросок 1–rollMax.
   - Повторные броски показываются в таблице.
   - Если сначала бросил не тот диапазон, засчитывается следующий правильный.
4. **Таблица:** место, игрок, роль, ролл, ±, итог, причина недопуска; победитель — со звездой и подсветкой.
   Наведите на строку — видно, за что у игрока минусы.
5. **Итог.**
   - Ничья на первом месте → переролл только для этих игроков (15 сек), итог считается так же.
   - Победитель объявляется в рейд-варнинг. Затем в /рейд каждый игрок отдельной строкой
     (до rollLines, по умолчанию 10): победитель со звездой, ничья с ромбом, незасчитанные с крестом.
   - «Закончить розыгрыш» досрочно закрывает приём бросков и пишет итог в чат.
   - Чужой ролл: в чат пишется только по «Закончить розыгрыш» или «Итог в чат». Если
     ответственный сам объявил победителя («выиграл»), наблюдение закрывается молча.
6. Текущий ролл живёт в памяти: после /reload посреди ролла его нужно начать заново.

## 8. Этапы

1. **Основа — готово (0.1.0).**
   - Своды и шаблоны, минусы кликом, журнал, объявления, шёпот.
   - Розыгрыш с минусами и киком, ролл на офф-спек.

   у каждого правила, цветные метки. Номера способностей сверить на Circle по `RaidMinusDB.spellLog`.

   от всех источников с фильтром гер. шмота, окно по боссам и лента, минус цели, мини-панель,

   [AUTOMATION.md](AUTOMATION.md) — по желанию РЛа.
5. **Выбрано РЛом дальше:**
   - итоги рейда в Discord через SkadaDiscord: минусы и кто что выиграл;
   - история нарушителей: минусы за прошлые рейды в подсказке («3-й рейд подряд дух на Леди»);
   - «Кто виноват?» после вайпа: окно с последними смертями, один клик — «вайп по вашей вине».
